# 11 — API Design

REST over JSON. Base path `/api/v1`. OpenAPI generated by FastAPI at `/api/v1/openapi.json`,
Swagger UI at `/docs` (disabled in production).

## 11.1 Conventions

| Concern | Rule |
|---|---|
| Resource naming | Plural nouns: `/workflows`, `/executions`, `/credentials` |
| Actions on a resource | Sub-path verb: `POST /workflows/{id}/activate` |
| Casing | **camelCase on the wire**, snake_case in Python (ADR-019) |
| IDs | UUIDv7 strings |
| Timestamps | ISO-8601 UTC with `Z`: `2026-09-07T14:03:22.481Z` |
| Nulls | Explicit `null`; a field is never silently omitted |
| Partial update | `PATCH` with only changed fields; `PUT` is not used |
| Deletion | `DELETE` returns `204` with no body |
| Versioning | URL path (`/api/v1`). A breaking change means `/api/v2` |

**Why URL versioning over headers:** it is visible in logs, curl-able, and cacheable. Header
versioning is more elegant and, in practice, harder to debug at 3am.

**Idempotency.** Any POST that creates a resource or triggers an execution accepts
`Idempotency-Key`. The key is stored in Redis for 24 hours mapped to the original response, so a
retried webhook or a double-clicked button cannot double-fire a workflow.

## 11.2 Authentication

Two schemes, both resolving to the same `RequestContext`:

```
Authorization: Bearer <jwt>              # interactive users; 15-min access token
Authorization: Bearer nf_live_<key>      # programmatic; scoped API key
```

Access tokens are short-lived; refresh tokens are rotated on every use and delivered as an
`HttpOnly; Secure; SameSite=Strict` cookie so the SPA never handles the long-lived credential in
JavaScript. Access tokens live in memory only — never `localStorage`, which is readable by any XSS.

## 11.3 Pagination

**Keyset (cursor) pagination for anything that grows without bound** — executions, audit logs,
agent runs, messages. Offset pagination on a 40-million-row table means `OFFSET 2000000`, which
Postgres services by walking two million rows.

```
GET /executions?limit=50&cursor=eyJjIjoiMjAyNi0wOS0wN1QxNDowMzoyMloiLCJpIjoiMDE5..."
```

```jsonc
{
  "items": [ /* … */ ],
  "nextCursor": "eyJjIjoiMjAy…",   // null when exhausted
  "hasMore": true
}
```

The cursor is base64 of `{created_at, id}` — the tiebreaker matters, or rows sharing a timestamp
are silently skipped or duplicated. Cursors are opaque to clients and MUST NOT be constructed
client-side.

Offset pagination is permitted only for small, bounded collections (projects, members,
credentials), where `total` is genuinely useful:

```jsonc
{ "items": [], "total": 42, "page": 1, "pageSize": 20 }
```

`limit` defaults to 20 and is capped at 100 everywhere.

## 11.4 Error format

One shape for every error, from every endpoint:

```jsonc
{
  "error": {
    "code": "workflow.validation_failed",
    "message": "Workflow has 2 validation errors.",
    "details": [
      { "field": "graph.nodes[3].parameters.url", "message": "URL is required.", "code": "required" }
    ],
    "requestId": "01931f2a-8c4e-7a11-b3d2-2f1c9e0a4d55"
  }
}
```

- `code` is stable and machine-readable. Clients branch on it. It never changes for a given
  condition, even if the message is reworded.
- `message` is human-facing and safe to display.
- `details` is present for validation errors; `field` uses dotted JSON paths so a form can map an
  error straight onto an input.
- `requestId` correlates with server logs and is what a user pastes into a support ticket.

| Status | When |
|---|---|
| 400 | Malformed request (bad JSON, bad cursor) |
| 401 | Missing/invalid/expired credentials |
| 403 | Authenticated but not permitted |
| 404 | Not found **or** not visible to this actor (never distinguish — that leaks existence) |
| 409 | Conflict: version mismatch, duplicate name, already active |
| 422 | Semantic validation failure |
| 429 | Rate limited (`Retry-After` header) |
| 500 | Unexpected — generic message, real detail only in logs |
| 502/503/504 | Upstream provider failure / dependency down |

## 11.5 Endpoints — auth

| Method | Path | Description |
|---|---|---|
| POST | `/auth/register` | Create account + default org/project |
| POST | `/auth/login` | Email + password → token pair |
| POST | `/auth/refresh` | Rotate refresh cookie → new access token |
| POST | `/auth/logout` | Revoke current refresh token |
| POST | `/auth/logout-all` | Revoke every session |
| POST | `/auth/forgot-password` | Send reset email (always 202 — no user enumeration) |
| POST | `/auth/reset-password` | Consume token, set password, revoke all sessions |
| GET | `/auth/me` | Current user + orgs + permissions |
| PATCH | `/auth/me` | Update own profile |
| POST | `/auth/change-password` | Requires current password |

```jsonc
// POST /auth/login
{ "email": "priya@acme.com", "password": "…" }
// 200
{ "accessToken": "eyJ…", "expiresIn": 900, "tokenType": "Bearer",
  "user": { "id": "019…", "email": "priya@acme.com", "name": "Priya",
            "organizations": [{ "id": "019…", "name": "Acme", "role": "admin" }] } }
// refresh token arrives as an HttpOnly cookie, never in this body
```

## 11.7 Endpoints — workflows

| Method | Path | Description |
|---|---|---|
| GET | `/workflows` | `?projectId=&search=&tag=&isActive=&limit=&cursor=` |
| POST | `/workflows` | Create (optionally from a template) |
| GET | `/workflows/{id}` | Detail incl. active version graph |
| PATCH | `/workflows/{id}` | Update name/settings/**graph** (creates a version) |
| DELETE | `/workflows/{id}` | Soft delete |
| POST | `/workflows/{id}/activate` | Validate + register triggers |
| POST | `/workflows/{id}/deactivate` | Unregister triggers |
| POST | `/workflows/{id}/duplicate` | Copy |
| POST | `/workflows/{id}/execute` | Manual run → `202 { executionId }` |
| GET | `/workflows/{id}/versions` | Version history |
| GET | `/workflows/{id}/versions/{versionId}` | One version's graph |
| POST | `/workflows/{id}/versions/{versionId}/restore` | Restore as a **new** version |
| GET | `/workflows/{id}/export` | Portable JSON (no secrets) |
| POST | `/workflows/import` | Import JSON |
| POST | `/workflows/{id}/validate` | Dry validation without saving |
| GET/PUT | `/workflows/{id}/pinned-data` | Editor sample data |

```jsonc
// PATCH /workflows/{id}
{
  "name": "Stripe → CRM sync",
  "baseVersionId": "019…",          // optimistic concurrency; 409 if stale
  "graph": { "nodes": [ /* … */ ], "edges": [ /* … */ ], "viewport": {…} },
  "settings": { "timezone": "Europe/London", "errorWorkflowId": null,
                "timeoutSeconds": 3600, "maxConcurrency": 1 }
}
// 200
{ "id": "019…", "name": "Stripe → CRM sync", "isActive": false,
  "activeVersionId": "019…", "version": 12, "updatedAt": "2026-09-07T14:03:22.481Z", "graph": {…} }
// 409
{ "error": { "code": "workflow.version_conflict",
             "message": "This workflow was modified by someone else.",
             "details": { "expectedVersionId": "019…", "actualVersionId": "019…" },
             "requestId": "…" } }
```

The 409 body carries the actual version id so the client can offer "reload theirs" or "overwrite"
without a second round trip.

## 11.8 Endpoints — executions

| Method | Path | Description |
|---|---|---|
| GET | `/executions` | `?workflowId=&projectId=&status=&mode=&from=&to=&limit=&cursor=` |
| GET | `/executions/{id}` | Detail + node runs (payloads by reference) |
| GET | `/executions/{id}/nodes/{nodeId}/data` | Input/output items for one node, paginated |
| POST | `/executions/{id}/cancel` | Cancel queued/running/waiting |
| POST | `/executions/{id}/retry` | `{ "fromFailedNode": true }` |
| POST | `/executions/{id}/resume` | Resume a waiting execution |
| DELETE | `/executions/{id}` | Delete one |
| POST | `/executions/bulk-delete` | `{ "filter": {…} }` |
| GET | `/executions/{id}/stream` | **SSE** live events |
| GET | `/executions/stats` | Aggregates for dashboard charts |

```
GET /executions/{id}/stream       Accept: text/event-stream

event: execution.started
data: {"executionId":"019…","status":"running","startedAt":"…"}

event: node.started
data: {"nodeId":"n_a1b2","nodeName":"Fetch customer","runIndex":0,"startedAt":"…"}

event: node.finished
data: {"nodeId":"n_a1b2","status":"success","itemsOut":24,"durationMs":412}

event: node.log
data: {"nodeId":"n_a1b2","level":"info","message":"Retrying after 429 (attempt 2/3)"}

event: execution.finished
data: {"executionId":"019…","status":"success","durationMs":3120}
```

Every event carries an `id:` so a dropped connection resumes with `Last-Event-ID`. A heartbeat
comment (`: ping`) every 15 seconds keeps proxies from closing an idle stream — omit it and
nginx will silently kill long-running executions' streams at 60s.

## 11.10 Endpoints — credentials

| Method | Path | Description |
|---|---|---|
| GET | `/credentials` | `?projectId=&type=` — **never returns secret data** |
| POST | `/credentials` | Create (encrypts server-side) |
| GET | `/credentials/{id}` | Metadata only |
| PATCH | `/credentials/{id}` | Update; omitted secret fields are left unchanged |
| DELETE | `/credentials/{id}` | Soft delete; 409 if in use by an active workflow |
| POST | `/credentials/{id}/test` | Live connection test |
| GET | `/credential-types` | Field schemas for the create form |
| GET | `/credentials/{id}/oauth/authorize` | Returns provider consent URL |
| GET | `/credentials/oauth/callback` | Provider redirect target |

```jsonc
// GET /credentials/{id}  — note the total absence of a data field
{ "id": "019…", "name": "Stripe production", "type": "stripeApi",
  "projectId": "019…", "lastTestedAt": "…", "testStatus": "ok",
  "usedByWorkflowCount": 3, "createdAt": "…" }
```

There is no `data` field, no masked value, no `"••••"`. The field does not exist on the read
schema, so no future refactor can accidentally populate it.

## 11.13 Rate limiting

Redis token bucket, applied per API key or per user, with per-IP limits on unauthenticated routes.

| Scope | Limit |
|---|---|
| Authenticated default | 600 req/min |
| `POST /auth/login` | 10 / 15 min per IP + per email |
| `POST /auth/register`, `/forgot-password` | 5 / hour per IP |
| Execution triggers | 60/min per workflow |
| `/webhook/*` | 1000/min per registration (configurable) |
| `load-options` | 30/min per credential |

Responses always carry `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; a 429
carries `Retry-After`. Login limits are keyed on **both** IP and email — IP-only is trivially
bypassed by a botnet, email-only lets one attacker lock out a real user.

## 11.14 Practices this API deliberately avoids

- **No `GET` with side effects.** Ever. Prefetchers and link scanners will find them.
- **No batch endpoint that mixes verbs.** `POST /batch` with heterogeneous operations makes
  authorization, partial failure, and idempotency unreasonable. Specific bulk endpoints
  (`/executions/bulk-delete`) are fine because they are one verb over one resource.
- **No nested resources deeper than two levels.** `/workflows/{id}/versions/{vid}` is the limit;
  beyond that, resources get top-level paths.
- **No returning 200 with an error body.** The status code is the contract.
- **No unbounded list endpoints.** Every collection paginates from day one, including ones that
  are "obviously small" — projects were obviously small until someone made four hundred.
